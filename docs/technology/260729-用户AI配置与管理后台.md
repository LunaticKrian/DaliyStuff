## 1. 背景与问题

当前 AI 模型/key/url **100% 写死在后端**：

- `server/app/config.py:14-16` 的 `ANTHROPIC_BASE_URL/AUTH_TOKEN/MODEL` 读自 `server/.env`（**明文 token 现躺在工作树里**，迁移后须轮换）。
- 三个 Agent 模块（`services/intel_agent.py:42-47`、`task_agent.py:35-39`、`resume_agent.py:40-44`）各自复制同一段「读 settings → 写 `os.environ`」的代码 —— 这是**有并发竞态的偷懒写法**：`os.environ` 是进程级全局，两个用户同时跑 Agent 会互相覆盖 key/model。
- 前端**完全感知不到模型**：AI 品牌硬编码 `NEXA`（`web/src/views/Chat.vue:206`），用户看不到也改不了模型。
- 全项目**无任何角色/admin 概念**（`User` 模型无 `is_admin`），没有用户管理、没有调用计量。

后果：多用户共用一把站点 key（成本/安全不可分摊）、无法自助切换模型、无后台可管。

## 2. 目标

1. **per-user AI 配置**：每个用户自助配 model/base_url/key/调用参数/附加系统提示；未配置则其 AI 功能（chat/resume/intel）不可用。
2. **安全存储**：用户 key 加密入库、读取掩码、绝不回显明文。
3. **管理后台**：超级管理员可管理用户（启停/提权）、查看各用户配置（掩码）、设配额、看调用统计与审计日志。
4. **intel per-user 化**：每日资讯按用户配置各自生成。
5. **消除竞态**：用 SDK 原生 per-query 注入替代全局 `os.environ` 写入。

**已定技术结论（已核 SDK 源码）**：`claude-agent-sdk` 的 `ClaudeAgentOptions` 原生支持 per-query 的 `env: dict`（`types.py:1869`）与 `model`（`:1820`）；子进程启动构造 `process_env = {**继承的 os.environ, **options.env}`（`_internal/transport/subprocess_cli.py:491-495`），即 options 覆盖全局。→ **per-user 注入零竞态，无需串行化。**

### 3.2 配置加密（`server/app/utils/crypto.py`）

- 用 `cryptography.fernet.Fernet`。主密钥来自 `settings.ENCRYPTION_KEY`（base64 的 32 字节）。
- **兜底**：未配置时从 `SECRET_KEY` 经 `PBKDF2HMAC(salt=fixed)` 派生（仅在自部署单机场景；文档警示生产应显式设 `ENCRYPTION_KEY`）。
- 接口：`encrypt(plain)->str` / `decrypt(cipher)->str` / `mask_key(plain)->str`（`sk-****<末4位>`，明文不足 8 位则全 `*`）。
- `requirements.txt` 加 `cryptography`。
- `config.py` 加 `ENCRYPTION_KEY: str | None = None`。

### 3.7 配额与用量统计

- **记账**：3 处 Agent 在拿到 `ResultMessage` 后写 `usage_records`（user_id / agent_type / model / 各 token / cost）。`cost_usd` 用模型价目表估算（`services/pricing.py`，本期仅 GLM 系列粗估，可后续细化）。

- **统计**：后台 `/api/admin/usage` 聚合 `usage_records`（按用户/模型/时间）。

## 7. 实现说明（与方案的偏差 / 落地细节）

实现已完成，构建通过（后端导入 + lifespan 建表/迁移/seed 烟雾测试、前端 `npm run build` 含 vue-tsc）。与 §3 的几点偏差：

1. **用户自配置页不含「用量/配额」面板**：未提供 `GET /api/me/usage` 端点；用量统计仅在管理后台（`/api/admin/usage`）可见。用户自己的配额由管理员设置，超限时 Agent 返回结构化错误事件（不抛异常）。
2. **配额编辑无回显接口**：只实现了 `PUT /api/admin/quota/{user_id}`（upsert），未做 `GET`。模态框以空白打开（留空 = 不限），并展示该用户当月已用 token / 成本作参考。
3. **角色徽标仅 ADMIN / USER**：未单独区分 SUPER（仅靠 `is_admin` 布尔，无更细角色字段）。
4. **测试连接**：`POST /api/me/ai-config/test` 可不传 body（测已保存配置）或传表单值（测未保存配置）；内部用 `ClaudeAgentOptions(env=…, model=…, max_turns=1)` 跑一次极小探测，按 `ResultMessage.subtype` 判定。
5. **每日资讯定时任务**：遍历 `user_ai_configs` 中 `enabled` 且 model/base_url/key 齐备的用户，**串行**逐个跑（复用全局 `_generate_lock`），单用户失败不影响其他。
6. **安全**：`utils/crypto.py` 用 Fernet；`ENCRYPTION_KEY` 未配时从 `SECRET_KEY` 经 PBKDF2 派生。`update_ai_config` 仅在传入「非空且不含 `****`」的 key 时才覆盖，避免前端误回填掩码串清掉密钥。
7. **超管 seed**：首启 `ensure_superadmin()` 创建 `super-hero`（`is_admin=True`、`must_change_password=True`、`profile_completed=True` 跳过角色建档引导）。明文口令取自 `SUPERADMIN_PASSWORD`（默认即预制值），入库即 bcrypt 哈希。
