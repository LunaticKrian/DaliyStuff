# 260727 · 鉴权会话化 + 桌面应用锁

> 状态：实现中（分支 `feat/260727-auth-sessions` / `feat/260727-desktop-applock`）
> 关联：`260726-桌面端客户端技术方案.md`（桌面瘦客户端）、`updaterule.md`（SOP）

## 1. 背景与问题

当前 JWT **完全无状态**（`server/app/routers/auth.py` / `utils/security.py` / `utils/deps.py`）：

- `/api/auth/refresh` 签新 refresh，**旧 refresh 永不失效** → 7 天内签发的每个 refresh 都长期有效且可续期。
- `/api/auth/logout` 是空壳，**不作废任何令牌**。
- 令牌只含 `sub`，**无 jti/会话/设备**，无法吊销单会话；改密码也不失效令牌。

后果：被窃 refresh token = ≥7 天可续期的持久沦陷，客户端登出挡不住。桌面端又把 refresh 长期存于钥匙串，正是收紧时机。

## 2. 目标

1. 服务端：**会话表 + refresh 轮换 + 会话级复用检测 + 真实登出/吊销**。
2. 前端：3 条独立 refresh 路径**收敛为单一去重 worker + 跨标签同步**（否则复用检测误伤正常多标签/HTTP+SSE 并发）。
3. 桌面：**应用锁（PIN + 生物识别）**。

**已定方案**：复用检测 = 会话级（仅吊销该会话族，不连坐其他设备）；应用锁 = PIN 必备 + 生物识别快捷。

## 3. 设计

### 3.1 数据模型（新表 `refresh_sessions`，`create_all` 自动建表）

| 字段 | 说明 |
|---|---|
| `id` PK | 即 token 中的 `sid`（稳定，access/refresh 共用） |
| `user_id` indexed | 所属用户（仓库无 FK 约定，保持一致） |
| `family_id` | UUID，标识一次登录的轮换链 |
| `current_jti` | 当前有效 refresh 的 jti；轮换时更新 |
| `device_name` / `device_platform` | 设备列表展示（登录时由 `X-Device-*` 头带入） |
| `created_at` / `last_seen_at` / `expires_at` | `expires_at` 滑动续期 |
| `revoked` | 吊销标志 |

### 3.2 令牌 claims

- access：`sub / exp / iat / type=access / sid`
- refresh：`sub / exp / iat / type=refresh / sid / jti`
- `sid` 稳定（access 校验靠它），`jti` 随轮换变（复用检测靠它）。

### 3.3 状态机（`server/app/services/session.py`）

- 登录/注册 → `create_session`（family_id、current_jti、expires_at=now+7d）→ 发 token。
- `/refresh`：decode → 取 `sid/jti` → 查会话；缺失/吊销/过期 → 401；**`current_jti != jti` → 复用 → `revoke_session`（仅本族）→ 401**；否则 `rotate_session`（新 jti、滑动续期）→ 发新对。
- `/logout`：`revoke_session(当前 sid)`（真实登出）。
- `/password`：成功后 `revoke_other_sessions`（踢其他设备、保留本机）。
- `GET /sessions` / `DELETE /sessions/{id}`：设备列表与踢设备。
- `get_current_user` 经 `get_current_session` 校验会话存活 → 吊销对 access **立即**生效（多一次 indexed SELECT，SQLite 个人应用可接受）。

### 3.4 前端收敛（`web/src/utils/refresh.ts`）

- 单一 `refreshTokens()`，模块级单例去重并发；成功广播 `BroadcastChannel('pxp-auth')` + `localStorage`。
- `client.ts` / `sse.ts` / auth store 三处 refresh 全部接入（消除 HTTP+SSE 同 tab 双刷）。
- `platform.ts` web 分支加 `storage` 事件 + BroadcastChannel 监听 → 跨标签同步内存 token；他 tab 被踢 → 本 tab 跳登录。
- `authStore.logout()` 先调 `POST /auth/logout` 再清 token。
- 修 `BlogEditor.vue` 绕过 tokenStore 的历史 bug。

### 3.5 桌面应用锁（PIN + 生物识别）

- PIN 哈希在 JS（Web Crypto SHA-256+盐）经既有 keychain 命令存取，**无新 Rust 命令/依赖**。
- 生物识别：`tauri-plugin-biometric`（⚠️ 实现期核实其 macOS 桌面覆盖；不覆盖则先只 PIN）。
- 锁状态机 `web/src/utils/appLock.ts`：空闲计时 + 失焦/最小化触发；锁屏屏蔽内容、解锁校验 PIN/生物识别。
- `Lock.vue` + 路由 `/lock` 守卫；`DesktopSettings.vue` 加锁设置分区。

## 4. 部署注意

- 服务端与前端 **同批上线**：旧 refresh token 无 `sid` → 首次 `/refresh` 401 → 用户一次性重登。
- 老客户端 `TokenResponse` 结构不变 → 仅需配套新前端以避免多标签自锁。

## 5. 验证

- 服务端：`pytest -q`（轮换/复用/登出/会话列表/踢设备/改密码）；httpie 手动。
- 前端：`npm run build`（vue-tsc）；两标签同账号不互踢。
- 桌面：`cargo check` + `npm run dev`（录 PIN/生物识别、空闲/最小化锁屏、两种解锁）。
