> 日期：2026-07-26

> 运行环境：**GLM（`https://open.bigmodel.cn/api/anthropic`）+ `claude-agent-sdk`**（复用世界地图 `intel_agent` 已验证模式）
> 关联设计稿：`design/260726-resume/`（`resume.html` 基础管理 · `chat.html` AI 编辑三栏）

## 1. Context（背景与目标）

PixelPack 已有完整的像素/RPG 个人管理系统（物品 / 角色 / 任务 / 冒险日志 / 世界地图）。本次新增「**冒险者履历 DOSSIER**」模块：把个人简历以「公会登记档案」的形式管理起来，并支持 **AI 对话编辑**。

核心需求（已与产品确认）：

1. **管理后台 + 实时预览**：左侧表单 CRUD，右侧 A4 简历纸实时渲染，可导出 PDF。
2. **视觉**：像素/RPG 外壳 + 内嵌专业衬线简历纸（投递可用）。
3. **AI 编辑**：对话式为主 + 字段内联润色，AI 产出的变更 **人工确认后才落库**。
4. **AI 取数方式**：**只读工具按需取**（`get_resume` / `get_section`），不把整份简历常驻 system prompt。
5. **版本化 + Undo**：每次接受变更即生成新版本，可回滚到任意历史快照。
6. **范围**：一步到位全量（对话 + 内联润色 + 多版本 + Undo）。

### 设计原则

- **AI 永不直接写库**。所有变更 → 后端 Pydantic 校验 → `pending` 待确认 → 用户接受 → 原子事务落库 + 存快照。
- **AI 只能通过工具修改**，禁止在回复正文里贴 JSON。
- **变更离散、可校验、可回滚**：采用语义化 Tool Calling，而非整份 JSON 重写或裸 JSON Patch。

## 2. 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| Web 框架 | FastAPI（async） | 复用 `server/app` 既有架构 |
| ORM | SQLAlchemy 2.0 (async) + SQLite (aiosqlite) | 复用 `app/database.py` |
| 认证 | JWT（`app/utils/deps.get_current_user`） | 与其它模块一致 |

## 3. 数据模型（`models/resume.py`）

一张简历 = 一个 `Resume`，其内容以 JSON 存于 `ResumeSnapshot.data`，每次接受变更即追加一条快照（版本）。AI 对话与待确认变更各自独立。

```python
# models/resume.py
from datetime import datetime
from sqlalchemy import DateTime, Integer, String, Text, ForeignKey, func
from sqlalchemy.orm import Mapped, mapped_column
from sqlalchemy.types import JSON
from app.database import Base


class Resume(Base):
    __tablename__ = "resumes"
    id: Mapped[int] = mapped_column(Integer, primary_key=True, autoincrement=True)
    user_id: Mapped[int] = mapped_column(Integer, index=True, nullable=False)
    title: Mapped[str] = mapped_column(String(120), default="我的简历", nullable=False)
    lang: Mapped[str] = mapped_column(String(8), default="zh", nullable=False)   # zh | en
    current_revision: Mapped[int] = mapped_column(Integer, default=1, nullable=False)
    created_at: Mapped[datetime] = mapped_column(DateTime, server_default=func.now())
    updated_at: Mapped[datetime] = mapped_column(DateTime, server_default=func.now(), onupdate=func.now())


class ResumeSnapshot(Base):
    """每次接受变更追加一条；data 存完整简历 JSON。Undo = 指向某个 snapshot。"""
    __tablename__ = "resume_snapshots"
    id: Mapped[int] = mapped_column(Integer, primary_key=True, autoincrement=True)
    resume_id: Mapped[int] = mapped_column(ForeignKey("resumes.id", ondelete="CASCADE"), index=True)
    revision: Mapped[int] = mapped_column(Integer, nullable=False)               # == Resume.current_revision
    data: Mapped[dict] = mapped_column(JSON, nullable=False)                     # 完整简历
    summary: Mapped[str] = mapped_column(String(160), default="")                # 本次变更一句话
    source: Mapped[str] = mapped_column(String(16), default="manual")            # manual | nexa
    created_at: Mapped[datetime] = mapped_column(DateTime, server_default=func.now())


class ResumeChatThread(Base):
    __tablename__ = "resume_chat_threads"
    id: Mapped[int] = mapped_column(Integer, primary_key=True, autoincrement=True)
    resume_id: Mapped[int] = mapped_column(ForeignKey("resumes.id", ondelete="CASCADE"), index=True)
    created_at: Mapped[datetime] = mapped_column(DateTime, server_default=func.now())


class ResumeChatMessage(Base):
    __tablename__ = "resume_chat_messages"
    id: Mapped[int] = mapped_column(Integer, primary_key=True, autoincrement=True)
    thread_id: Mapped[int] = mapped_column(ForeignKey("resume_chat_threads.id", ondelete="CASCADE"), index=True)
    role: Mapped[str] = mapped_column(String(16), nullable=False)                # user | assistant | tool
    content: Mapped[str] = mapped_column(Text, default="")
    tool_calls: Mapped[list | None] = mapped_column(JSON, nullable=True)         # AI 产出的工具调用
    created_at: Mapped[datetime] = mapped_column(DateTime, server_default=func.now())


class PendingChange(Base):
    """AI 产出、待用户确认的变更。接受/拒绝后置 status。"""
    __tablename__ = "resume_pending_changes"
    id: Mapped[int] = mapped_column(Integer, primary_key=True, autoincrement=True)
    resume_id: Mapped[int] = mapped_column(ForeignKey("resumes.id", ondelete="CASCADE"), index=True)
    thread_id: Mapped[int] = mapped_column(ForeignKey("resume_chat_threads.id"), index=True)
    group_id: Mapped[str] = mapped_column(String(32), default="")                # 一条指令可能产出多条，整组接受/拒绝
    tool: Mapped[str] = mapped_column(String(40), nullable=False)                # rewrite_section / add_entry ...
    args: Mapped[dict] = mapped_column(JSON, nullable=False)                     # 工具入参
    diff: Mapped[dict] = mapped_column(JSON, nullable=False)                     # {path, before, after}
    base_revision: Mapped[int] = mapped_column(Integer, nullable=False)          # 产出时基于的版本（冲突检测）
    status: Mapped[str] = mapped_column(String(12), default="pending")           # pending | applied | denied
    created_at: Mapped[datetime] = mapped_column(DateTime, server_default=func.now())
```

### 简历 JSON 结构（`ResumeSnapshot.data`）

```jsonc
{
  "profile": { "name": "", "title": "", "location": "", "years": "",
               "phone": "", "email": "", "site": "", "github": "" },
  "timeline": [ { "type": "work|edu", "role": "", "org": "", "date": "", "desc": "" } ],
  "project":  [ { "name": "", "stack": "", "desc": "" } ],
  "skill":    [ { "cat": "", "tags": [] } ],
  "award":    [ { "name": "", "issuer": "", "year": "" } ]
}
```

## 4. REST API 设计（`routers/resume.py`，prefix `/api/resume`）

### 4.1 简历 CRUD（手动编辑）

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/` | 创建空简历（含初始 snapshot r1） |
| `GET` | `/{rid}` | 取当前简历（=`current_revision` 对应 snapshot 的 data） |
| `PUT` | `/{rid}` | 整体保存手动编辑 → 追加新 snapshot，`current_revision++` |
| `DELETE` | `/{rid}` | 删除简历（级联快照/对话/待确认） |
| `GET` | `/mine` | 当前用户的简历列表 |

> 手动 `PUT` 与 AI 接受变更走**同一个**「落库 → 追加快照 → 版本++」内部函数 `apply_and_snapshot()`，保证版本链单一来源。

### 4.2 AI 对话（SSE）

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/{rid}/threads` | 新建对话线程 |
| `GET` | `/{rid}/threads/{tid}/messages` | 取历史消息 |
| `POST` | `/{rid}/threads/{tid}/chat` | **SSE 流**：发一句，流式返回文本 + tool_call |
| `POST` | `/{rid}/inline-polish` | 内联润色（单字段，等价一次 `rewrite_section`，同步返回一条 PendingChange） |

### 4.3 待确认变更

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/{rid}/pending` | 列出该简历所有 `pending` 变更（按 group 聚合） |
| `POST` | `/{rid}/pending/{pid}/accept` | 接受单条 → 事务应用 → 新 snapshot |
| `POST` | `/{rid}/pending/{gid}/accept-group` | 按 `group_id` 整组接受 |
| `DELETE` | `/{rid}/pending/{pid}` | 拒绝（status=denied） |

### 4.4 版本管理

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/{rid}/versions` | 版本时间线（revision / summary / source / created_at） |
| `POST` | `/{rid}/revert/{revision}` | 回滚到指定版本 → 把该 snapshot 内容作为新版本追加（不破坏历史） |
| `GET` | `/{rid}/versions/{a}/diff/{b}` | 两个版本的差异（供前端展示） |

## 5. SSE 事件协议（`/{rid}/threads/{tid}/chat`）

`Content-Type: text/event-stream`，每条事件用 SSE 的 `event:` 字段区分类型：

```
event: text
data: {"delta": "已读取履历"}

event: tool_call
data: {"tool": "rewrite_section", "args": {...}, "diff": {...},
       "pending_id": 42, "group_id": "g_8f3a", "base_revision": 7}

event: tool_call
data: {"tool": "update_profile", ...}     # 同一指令可连发多条（整组）

event: done
data: {"message_id": 123}

event: error
data: {"code": "TOOL_VALIDATE_FAIL", "message": "index 越界", "tool": "update_entry"}
```

前端按事件分流：`text` → 打字机回显；`tool_call` → 渲染拟变更卡片（带 `pending_id`）；`done` → 收尾。

## 6. Agent 与工具集（`services/resume_agent.py`）

### 6.1 只读工具（MCP server / 函数工具，按需取）

| 工具 | 入参 | 返回 | 说明 |
|---|---|---|---|
| `get_resume` | — | 完整紧凑快照 | AI 需要全局视图时调用 |
| `get_section` | `name` | 单板块数据 | profile/timeline/project/skill/award |
| `diff_version` | `a, b` | 两版本差异 | 辅助用户决策 |

> 实现：可作为一个轻量 MCP server 暴露给 Agent SDK（与项目既有「自定义 MCP 工具」模式一致），或直接以函数工具注册。**不**把简历塞进 system prompt。

### 6.2 写工具（产出 PendingChange，不落库）

| 工具 | 入参 | 语义 |
|---|---|---|
| `update_profile` | `field, value` | 改基本信息字段 |
| `add_entry` | `section, entry` | 新增一条（timeline/project/skill/award） |
| `update_entry` | `section, index, patch` | 修改某条 |
| `delete_entry` | `section, index` | 删除某条 |
| `reorder_entries` | `section, indices` | 重排 |
| `rewrite_section` | `section, index_or_range, instruction` | **文案改写专用**：模型按 instruction 重写，内部拆成 `update_entry` |
| `translate` | `lang` | 整份中英互译，内部拆成多条 `update_*` |

每个写工具的执行逻辑统一为：

1. 读 `base_revision` 对应 snapshot 的 data；
2. 计算理论 `diff`（before / after）；
3. **Pydantic 校验**入参（越界 index、非法 section/field 直接 raise → SSE 发 `error` 事件，回喂模型重试）；
4. 写入 `PendingChange`（status=pending），返回 `pending_id`；
5. SSE 推 `tool_call` 事件给前端。

### 6.3 系统提示约束（写进 system prompt）

```
你是 PixelPack 的简历军师 NEXA。规则：
1. 只能通过提供的工具修改简历，禁止在回复正文里输出 JSON 或简历原文。
2. 修改前先 get_section 了解现状；信息不足时反问用户，不得编造公司/职位/年份/数据。
3. 文案改写优先：动词前置、量化成果、去套话。
4. 语言跟随简历当前语种；translate 例外。
5. 一次复杂指令可连续产出多个工具调用（同 group），由用户整组确认。
```

### 6.4 Agent 运行（复用 `intel_agent` 模式）

- 环境变量：复用 `.env` 的 `ANTHROPIC_BASE_URL` / `ANTHROPIC_AUTH_TOKEN` / `ANTHROPIC_MODEL`（GLM）。
- 并发控制：每个 `thread_id` 一把 `asyncio.Lock`，禁止同线程并发跑两个 Agent（借鉴 `routers/chat.py` 的 `_session_locks`）。
- 流式：Agent SDK 的流式输出 → 转成上节 SSE 事件。

## 7. PendingChange 落库流程（核心闭环）

```
SSE tool_call
   │ 后端 Pydantic + 业务校验
   ▼
PendingChange{ tool, args, diff, base_revision }  入库 status=pending
   │ SSE 推送
   ▼
前端拟变更卡片
   ├─ 接受  POST /pending/{pid}/accept
   │     └─ 校验 base_revision == resume.current_revision
   │          ├─ 相等：apply_and_snapshot() 事务内
   │          │     · 应用 args 到 data
   │          │     · 追加 ResumeSnapshot(revision=++current)
   │          │     · Resume.current_revision++
   │          │     · PendingChange.status=applied
   │          └─ 不等：返回 409 Conflict（前端重拉 diff / 提示冲突）
   └─ 拒绝  DELETE /pending/{pid}  → status=denied
```

`apply_and_snapshot(db, resume, data, summary, source)` 是手动 `PUT` 与 AI 接受共用的唯一落库函数，确保版本链一致。

**整组接受**：同一 `group_id` 的多条 PendingChange 在一个事务内顺序应用，任一条冲突则整组回滚。

## 8. 版本化与 Undo

- 每次接受 / 手动保存 → 追加 `ResumeSnapshot`，`revision` 单调递增。
- **Undo / 回滚**（`POST /{rid}/revert/{revision}`）：把目标 snapshot 的 `data` 作为**新 revision** 追加（而非删除中间版本），历史不可变，永远可再回滚。
- `source` 字段区分 `manual` / `nexa`，前端版本时间线据此标注来源徽标。

## 9. 安全与边界

| 风险 | 处置 |
|---|---|
| AI 编造事实 | Prompt 约束 + 信息不足反问；不主动生成新公司/年份 |
| 越界 index / 非法字段 | 写工具 Pydantic 校验，失败发 `error` 事件回喂 |
| 并发冲突 | `base_revision` 乐观锁，接受时校验，不等返回 409 |
| 同线程并发 Agent | `asyncio.Lock` per thread |
| 跨用户越权 | 所有端点 `Depends(get_current_user)` + 校验 `resume.user_id` |
| Token 成本 | 只读工具按需取，不整份常驻 prompt |
| 简历体积 | snapshot JSON 限长（profile 字段 / 数组条数上限校验） |

## 10. 落地阶段（提交顺序）

1. **地基**：`Resume` / `ResumeSnapshot` 模型 + CRUD + `apply_and_snapshot` + 版本列表/回滚。（先把「可撤销的简历」做扎实，AI 改错也有兜底）
2. **只读管线**：Resume MCP 只读工具 + Agent 对话 SSE（只读 + 闲聊），跑通 GLM 流式。
3. **写闭环**：写工具 + `PendingChange` + 拟变更卡片前端 + accept/deny + 409 冲突。
4. **内联润色 + 整组**：`/inline-polish` + `accept-group`。
5. **版本 UI**：版本时间线 + `diff_version` 工具辅助决策。

## 11. 待确认 / 开放项

- **MCP server 形态**：简历只读工具是独立 MCP server，还是直接以函数工具注册到 Agent SDK？前者更解耦、可复用，后者更轻。倾向独立 MCP server，与项目既有模式一致。
- **多份简历**：当前模型已支持一人多份（`Resume` 1—n），是否需要「默认简历」概念？
- **PDF 导出**：前端 `window.print()` + `@media print`（设计稿已实现）；若要服务端导出，再评估 WeasyPrint。
- **简历模板**：当前一套「公会登记纸」模板，后续是否支持多模板切换（影响 snapshot.data 是否带 template 字段）。
