## 1. Context（背景与目标）

PixelPack 当前是标准 CS 架构的 Web 站点：浏览器（Vue 3）↔ FastAPI 服务端，经 `airise-gateway` 终结 TLS 反代，挂在 `*.airise.site`（HTTPS）。本次新增**桌面端原生 App**，让用户在桌面拥有「常驻可达、原生通知、本地文件集成、断网可读」的原生体验。

### 核心需求（已与产品确认）

1. **client + server 组合**：桌面端是**瘦客户端**，所有数据接口与后端服务**仍在线上服务器**（`api` 容器不变）。桌面端只做 UI + 调 API + 原生能力。
2. **桌面先行，移动在后**：本次只实现桌面（macOS / Windows，Linux 次要）；**但选型须为未来移动端（iOS/Android）留路**。
3. **原生能力（全选）**：系统托盘 + 常驻 + 全局快捷键 + 开机自启、原生系统通知、本地文件/文件夹集成、断网只读缓存。
4. **数据模式**：**在线为主 + 轻量只读缓存**——服务器是唯一数据源，桌面端仅缓存最近响应用于提速与断网只读，**不本地写入、不双向同步**。
5. **UI 复用**：**混合**——外壳与绝大多数页面复用 `web/` 现有 Vue SPA，仅桌面专属页（首屏服务器配置、桌面设置、托盘菜单）定制。

### 设计原则

- **服务端零改动为第一目标**。当前 CORS 已是 `allow_origins=["*"]`，桌面 webview 跨域调用已放行；除可选的「图片返回绝对 URL」优化外，**不动 FastAPI 任何路由与模型**。
- **前端单代码库**。桌面端不 fork `web/`，而是在 `web/` 内引入平台层（`isTauri()` 分支），桌面专属页与原生调用走 `#[cfg(desktop)]` / 运行时门控；Web 与桌面共享同一套 Vue 代码。
- **令牌不落明文盘**。JWT 不再写 `localStorage`，桌面端经 Rust 命令写入 **OS Keychain**（macOS Keychain / Windows Credential Manager / Linux Secret Service）；Web 端行为不变。
- **原生能力可降级**。任何原生调用在 Web 端必须 no-op 或回退到浏览器实现，保证 `web/` 仍能纯浏览器访问。

## 2. 选型结论（含否决项）

| 维度 | 选择 | 理由 |
|---|---|---|
| 外壳框架 | **Tauri 2** | 系统 WebView（无捆绑 Chromium），产物小（~8–12MB）、内存省；**Rust 核心 + 同一套前端可直接扩展到 iOS/Android**，契合「未来做移动端」；安全模型（capabilities/ACL）细粒度可控。 |
| 前端 | 复用 `web/`（Vue 3.5 + Vite） | 现成 ~20 个 view + 像素设计系统，零业务重写；桌面 = 外壳 + 平台层改造。 |
| 服务器 | **完全不动** | 数据/接口/网关维持现状；桌面端经 HTTPS/WSS 直连。 |
| 令牌存储 | OS Keychain（`keyring` crate） | 单用户桌面场景下安全性优于 localStorage；Web 端维持 localStorage。 |
| 离线策略 | ofetch 响应级 IndexedDB 只读缓存 | 在线优先，仅 GET 缓存；断网/出错回源缓存；无写回、无冲突。 |
| 自动更新 | `tauri-plugin-updater` + 签名 | 自托管静态清单或 GitHub Releases；产物需签名（macOS 公证 / Windows 可选）。 |

### 否决项

- **Electron**：生态最成熟、纯 JS，但产物 ~150MB、内存高，且**无官方移动端路径**——移动端将来需另起一套（React Native/Capacitor），与「单代码库」目标冲突。本轮已选「未来要做移动端」，故否决。
- **PWA / 轻量 WebView 壳（Pake 等）**：最快但原生能力极弱，无法满足「托盘/全局快捷键/系统通知/自启」全选诉求，后续扩展天花板低。
- **Flutter / Qt**：与现有 Vue 生态割裂，前端需整体重写，违反「服务端不动 + 前端单代码库」原则。

### 数据流

- **业务读写**：WebView 内 `ofetch` 直接请求 `https://<server-origin>/api/...`（CORS `*` 已放行，无需 Rust 代理）。响应经只读缓存拦截器按需落 IndexedDB。
- **图片**：后端返回相对 `/uploads/<file>`，前端响应归一化层补全为 `https://<server-origin>/uploads/<file>`（见 §5.2）。
- **流式 / 实时**：SSE（AI 对话 / 资讯 / 简历编辑）与 WebRTC 信令 WebSocket（`/api/rtc/signal`）在 WebView 内原生支持，走 `https/wss`，复用现有网关的 ws 升级配置。
- **原生能力**：托盘/快捷键/通知/自启/文件集成经 Tauri 插件 + Rust 命令；前端通过 `@tauri-apps/api` 调用，Web 端经 `native.ts` 抽象层降级为 no-op。

## 5. 关键技术点与改造清单

### 5.1 服务器地址可配（去掉相对 `/api`）

现状：`client.ts` 写死 `baseURL: '/api'`（相对），依赖浏览器同源 + Vite 代理。桌面 WebView 的 origin 是 `tauri://localhost`（Windows 为 `http://tauri.localhost`），相对 `/api` 会解析到错误地址。

方案：

- `platform.ts` 暴露 `getServerOrigin()`：桌面端从 `tauri-plugin-store` 读取用户配置的 server origin（首屏设置，见 §7）；Web 端返回 `''`（保持相对）。
- `client.ts` 的 `baseURL` 改为动态：`() => `${getServerOrigin()}/api``。首屏未配置时，桌面端强制路由到 Setup 页。
- 服务器 origin 仅允许 `https://`（生产）或 `http://localhost`（本地调试），输入时校验。

```ts
// web/src/utils/platform.ts（节选）
import { store } from '@tauri-apps/plugin-store' // 仅桌面可用，动态 import

const SERVER_ORIGIN_KEY = 'server.origin'

export function isTauri(): boolean {
  return typeof window !== 'undefined' && '__TAURI_INTERNALS__' in window
}

export async function getServerOrigin(): Promise<string> {
  if (!isTauri()) return '' // Web：相对路径，走同源 / 网关
  const s = await (await import('@tauri-apps/plugin-store')).load('app.json')
  const origin = (await s.get<string>(SERVER_ORIGIN_KEY)) ?? ''
  if (!origin) throw new Error('SERVER_NOT_CONFIGURED') // 触发首屏引导
  return origin.replace(/\/$/, '')
}

export async function setServerOrigin(origin: string) {
  const s = await (await import('@tauri-apps/plugin-store')).load('app.json')
  await s.set(SERVER_ORIGIN_KEY, origin)
  await s.save()
}
```

> `client.ts` 现为同步 `baseURL`；改异步 origin 后，需在应用初始化阶段（`main.ts` / 路由守卫）先 `await getServerOrigin()` 注入到全局变量，再挂载 API 实例，避免每个请求都 await。

### 5.2 `/uploads` 资源地址归一化

现状：后端返回的图片字段（`portrait_url` / `cover_url` / `images[].url` / `thumb_url`）是相对 `/uploads/<file>`，模板直接 `<img :src="x.url">`（`ItemList`/`Dashboard`/`Quests`/`BlogList`/`ItemForm` 等 ~10 处）。桌面下相对路径解析到 `tauri://localhost/uploads/...` → 404。

方案（**集中式响应归一化，零模板改动**）：在 `client.ts` 的 `onResponse` 中，对 JSON 响应递归遍历，把所有 `^/uploads/` 字符串补上 `getServerOrigin()` 前缀。Web 端 origin 为 `''`，等价于不改（no-op）。

```ts
function absolutizeUploads(node: any, origin: string) {
  if (typeof node === 'string' && node.startsWith('/uploads/'))
    return origin + node
  if (Array.isArray(node)) return node.map((n) => absolutizeUploads(n, origin))
  if (node && typeof node === 'object')
    for (const k of Object.keys(node)) node[k] = absolutizeUploads(node[k], origin)
  return node
}
// onResponse({ response }) { if (origin && response._data) absolutizeUploads(response._data, origin) }
```

> 备选：模板级 `assetUrl()` helper + codemod ~10 处 `:src`。响应归一化更省且覆盖未来新增字段，**作为首选**。

### 5.3 令牌安全存储（OS Keychain）

现状：JWT 存 `localStorage`（`auth.ts` 6 处、`sse.ts` 3 处、`client.ts` 6 处、`Transfer.vue` 1 处）。桌面端 localStorage 落在 app 数据目录的明文 webview 存储，不够安全。

方案：引入 **storage 适配器**，对外暴露 `getToken / setToken / clearTokens`，桌面端走 Rust keychain 命令，Web 端走 localStorage。

```ts
// web/src/utils/platform.ts
export const tokenStore = {
  async get(k: string) {
    if (!isTauri()) return localStorage.getItem(k)
    return await (await import('@tauri-apps/api/core')).invoke<string | null>('get_secret', { key: k })
  },
  async set(k: string, v: string) {
    if (!isTauri()) return localStorage.setItem(k, v)
    await (await import('@tauri-apps/api/core')).invoke('set_secret', { key: k, value: v })
  },
  async del(k: string) { /* 同上 */ },
}
```

```rust
// application/desktop/src-tauri/src/commands/secret.rs
use keyring::Entry;

#[tauri::command]
pub fn set_secret(key: &str, value: &str) -> Result<(), String> {
    Entry::new("PixelPack", key).map_err(|e| e.to_string())?
        .set_password(value).map_err(|e| e.to_string())
}
#[tauri::command]
pub fn get_secret(key: &str) -> Result<Option<String>, String> {
    match Entry::new("PixelPack", key).map_err(|e| e.to_string())?.get_password() {
        Ok(v) => Ok(Some(v)),
        Err(keyring::Error::NoEntry) => Ok(None),
        Err(e) => Err(e.to_string()),
    }
}
```

> 迁移：把 `auth.ts`/`client.ts`/`sse.ts`/`Transfer.vue` 中的 `localStorage.getItem('access_token')` 等替换为 `await tokenStore.get(...)`。`client.ts` 的 `onRequest` / `onResponseError` 改为异步读 token（ofetch 支持异步 `onRequest`）。

### 5.4 401 跳转改为路由内跳转（去 `window.location`）

现状：`client.ts`(2 处) 与 `sse.ts`(2 处) 在 401 / 刷新失败时 `window.location.href = '/login'`。桌面 WebView 下 `tauri://localhost/login` 无 SPA 回退，会白屏。

方案：`platform.ts` 提供注册式 `setRedirector(fn)`，由 `main.ts` 注入 Vue Router 的 `push`；上述 4 处改为调用 `redirector('/login')`。Web 端若未注入则回退 `window.location`（保持原行为）。

```ts
let redirector: (path: string) => void = (p) => (window.location.href = p)
export function setRedirector(fn: (path: string) => void) { redirector = fn }
export function redirect(path: string) { redirector(path) }
// main.ts: setRedirector((p) => router.push(p))
```

### 5.5 SSE / WebRTC 信令在 WebView

- **SSE**（`utils/sse.ts`）：WebView 原生支持 `EventSource`，地址需用绝对 `https://<origin>/api/...`（复用 `getServerOrigin()`）；鉴权 header 同样从 `tokenStore` 异步取。
- **WebRTC 信令**（`/api/rtc/signal` WebSocket）：WebView 支持，需 `wss://<origin>/api/rtc/signal`，首帧 JWT 鉴权不变。网关已开 ws 升级 + buffering off。
- CSP（见 §6）须在 `connect-src` 放开 `https:` 与 `wss:`。

### 5.6 轻量只读缓存（在线为主）

策略：**响应级、仅 GET、IndexedDB、出错回源**。

- 在 `client.ts` 包一层：成功 GET 响应按 `method+url+JSON.stringify(params)` 写入 IndexedDB（带时间戳）；**不缓存** POST/PUT/PATCH/DELETE。
- `onResponseError`（或 fetch reject）且为 GET 时，命中缓存则返回缓存（标记 `stale: true`，UI 可提示「离线数据」）。
- 容量上限：LRU 淘汰，总条数上限（如 500）+ 单 key TTL（如 24h）；首屏设置页提供「清空缓存」。
- **不做写回、不做失效广播**。可选轻量失效：成功 mutating 同资源集合时删除其列表缓存 key（按路径前缀匹配）。

```ts
// web/src/api/cache.ts（节选）
const MAX = 500
export async function cacheGet(key: string) { /* idb-keyval get + TTL 校验 */ }
export async function cacheSet(key: string, data: any) { /* set + LRU 裁剪 */ }
export async function cacheInvalidate(prefix: string) { /* 删除同前缀 key */ }
```

> 缓存层与 §5.2 的 uploads 归一化顺序：先归一化（写入的是补全后的绝对 URL 图片），再缓存——保证离线时图片地址也正确。

## 6. 关键约束与前置条件

### 6.1 CSP（Tauri 2 安全模型，关键 gotcha）

`tauri.conf.json` 的 `app.security.csp` 默认较严。桌面 WebView 需向**用户配置的远端 origin** 发起 `https`/`wss` 并加载其图片。因 origin 运行时可配，采用：

```
default-src 'self'; img-src 'self' https: data: blob:;
connect-src 'self' https: wss:; style-src 'self' 'unsafe-inline'; font-src 'self' data:;
```

- `connect-src https: wss:`：放开 API/SSE/WS 目标（origin 用户自控，可接受）。
- `img-src https:`：放开 `/uploads` 图片。
- **不引入 `unsafe-eval`**（Vite 生产构建无需 eval）。

### 6.2 CORS

服务端 `allow_origins=["*"]` 已满足跨域调用，**无需改动**。桌面 WebView origin（`tauri://localhost` / `http://tauri.localhost`）对远端 API 属跨域，被 `*` 放行。

### 6.3 安全上下文

SSE / WebRTC 在 WebView 内等价安全上下文（非 http 明文页面），可用。生产 origin 必须 `https`（首屏校验）。

### 6.4 签名 / 公证（分发前置）

- **macOS**：需 Developer ID 签名 + 公证（`notarytool`），否则 Gatekeeper 拦截。`tauri build` 接 `APPLE_SIGNING_IDENTITY` / `APPLE_ID` 等环境变量。
- **Windows**：推荐 EV / OV 代码签名证书（可选；未签名时 SmartScreen 警告）。
- **更新签名**：`tauri-plugin-updater` 要求更新包签名（`UPDATER_PRIVATE_KEY`），公钥写进 `tauri.conf.json`。

### 6.5 平台一致性

- 系统要求：macOS 11+（WKWebView）、Windows 10+（WebView2，随系统或捆绑 bootstrapper）、Linux（WebKitGTK，发行版差异较大，**作为次要目标**）。
- 桌面端**不碰** `claude-agent-sdk` 的 240MB glibc 二进制问题（那是服务端镜像的事），桌面端是纯客户端。

## 9. 移动端演进路径（为未来留路）

- Tauri 2 原生支持 iOS / Android，**共享同一 Rust 核心 + Vue 前端**。
- 桌面专属插件（autostart / global-shortcut / 托盘）需门控：
  - Rust：`#[cfg(desktop)]` + Cargo `[features] desktop = [...]`，移动端不编译。
  - 前端：`api/native.ts` 内按 `platform()`（`@tauri-apps/plugin-os`）分发；移动端替换为移动等价能力（如通知用移动推送）。
- 首屏服务器配置、只读缓存、令牌 keychain（iOS Keychain / Android Keystore 同样走 `keyring` 或平台插件）逻辑**可直接复用**。
- **结论**：本轮桌面选型不会成为移动端的沉没成本。

## 12. 风险与回退

| 风险 | 影响 | 缓解 |
|---|---|---|
| Rust 工具链引入，团队不熟 | 构建门槛 | 外壳 Rust 量小（命令 + 插件装配）；JS 侧仍是主力；CI 跑构建 |
| 系统差异大（尤其 Linux WebKitGTK） | 渲染/能力不一致 | macOS/Windows 为主，Linux 标注「次要」；CI 矩阵覆盖前两者 |
| CSP 配置不当导致 API/图片被拦 | 全站不可用 | §6.1 明确 `connect-src`/`img-src` 放开；首屏连通性测试 |
| keychain 在某些 Linux 无 Secret Service | token 存不了 | `keyring` 失败时回退到 `tauri-plugin-store`（加密配置）+ UI 提示 |
| 签名/公证证书缺失 | 无法分发 | P0–P2 可用未签名本地包自测；分发阶段再补证书；自动更新必须签名 |
| Web 端回归 | 改动波及 Web | 所有原生/平台分支以 `isTauri()` 门控，Web 路径行为不变；`npm run build`(vue-tsc) 守底 |

> 回退：若 Tauri 评估不达预期，外壳层与 `web/` 解耦——`web/` 的平台改造（origin/token/路由/缓存）对任何 WebView 方案通用，可平移到 Electron/Pake，**不产生沉没成本**。
